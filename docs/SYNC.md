# 数据同步使用指南

## 一、架构说明

### 本地客户端
- **数据库**：SQLite（本地文件，无需安装数据库服务器）
- **功能**：完整的财务管理和数据录入
- **同步**：可选，可配置自动同步到云端

### 云端服务器
- **数据库**：MySQL（集中存储所有数据）
- **功能**：数据同步 API、数据合并、冲突解决
- **部署**：需要部署到服务器（Linux/Windows）

## 二、快速开始

### 2.1 仅使用本地（不部署云端）

1. 直接运行 `manage-agent.exe`
2. 数据存储在本地 SQLite 文件 `./data/manage-agent.db`
3. 无需任何配置，开箱即用

### 2.2 使用云端同步（需要部署云端服务器）

#### 步骤1：部署云端服务器

参考 [部署指南](./DEPLOY.md) 部署云端服务器。

#### 步骤2：配置本地客户端

编辑 `bin/config.json`：

```json
{
    "database": {
        "type": "sqlite",
        "sqlite": {
            "path": "./data/manage-agent.db"
        }
    },
    "sync": {
        "enabled": true,
        "cloud_api_url": "http://your-server:8080",
        "auto_sync_interval": 300
    }
}
```

配置说明：
- `enabled`: `true` 启用同步，`false` 禁用
- `cloud_api_url`: 云端服务器地址（必须包含协议和端口）
- `auto_sync_interval`: 自动同步间隔（秒），`0` 表示不自动同步

#### 步骤3：启动本地客户端

运行 `manage-agent.exe`，程序会自动：
1. 每 5 分钟（如果配置了 `auto_sync_interval`）自动同步
2. 上传本地未同步数据到云端
3. 下载云端新数据到本地

## 三、同步机制

### 3.1 数据状态

每条数据都有 `sync_status` 字段：
- `0`：未同步（本地新创建的数据）
- `1`：已同步（已上传到云端）

### 3.2 同步流程

```
本地创建数据
    ↓
sync_status = 0（未同步）
    ↓
自动同步触发（或手动触发）
    ↓
上传到云端 → 云端合并数据
    ↓
标记 sync_status = 1（已同步）
    ↓
下载云端新数据 → 合并到本地
```

### 3.3 冲突解决

当同一数据在多个设备上被修改时：
- **策略**：基于时间戳（`updated_at`）
- **规则**：更新时间更晚的数据优先
- **结果**：自动合并，无需手动处理

## 四、API 说明

### 4.1 上传数据

**端点**：`POST /api/v1/sync/upload`

**请求体**：
```json
{
    "worth_records": [
        {
            "time": "2024-01-01 12:00:00",
            "cash": 10000.00,
            "stock_a": 5000.00,
            ...
        }
    ],
    "flow_records": [
        {
            "time": "2024-01-01 12:00:00",
            "type": "cash",
            "value": 1000.00
        }
    ],
    "last_sync_time": "2024-01-01T00:00:00Z"
}
```

### 4.2 下载数据

**端点**：`GET /api/v1/sync/download?last_sync_time=2024-01-01T00:00:00Z`

**响应**：
```json
{
    "code": 200,
    "msg": "success",
    "data": {
        "worth_records": [...],
        "flow_records": [...],
        "last_sync_time": "2024-01-01T12:00:00Z"
    }
}
```

## 五、手动同步

如果需要手动触发同步，可以使用以下方法：

### 方法1：修改配置文件

将 `auto_sync_interval` 设置为较小的值（如 60 秒），然后重启程序。

### 方法2：使用 API（如果实现了手动同步接口）

```bash
curl -X POST http://localhost:8090/api/v1/sync/manual
```

## 六、故障排查

### 问题1：同步失败

**检查项**：
1. 云端服务器是否正常运行
2. `cloud_api_url` 配置是否正确
3. 网络连接是否正常
4. 查看日志文件 `log/latest.json`

### 问题2：数据冲突

**说明**：系统会自动解决冲突，基于时间戳选择最新数据。

**查看冲突**：检查日志中的同步记录。

### 问题3：同步速度慢

**优化建议**：
1. 增加 `auto_sync_interval`（减少同步频率）
2. 检查网络带宽
3. 优化云端服务器性能

## 七、最佳实践

1. **定期备份**：即使有云端同步，也建议定期备份本地 SQLite 文件
2. **网络环境**：确保客户端能访问云端服务器
3. **同步频率**：根据数据更新频率调整 `auto_sync_interval`
4. **离线使用**：即使无法连接云端，本地功能完全可用

## 八、安全建议

1. **HTTPS**：生产环境建议使用 HTTPS
2. **认证**：如果需要，可以添加 JWT 认证（当前版本未实现）
3. **防火墙**：限制云端服务器的访问 IP
4. **数据加密**：敏感数据建议加密存储
